# URL Shortener Service Specification

## 1. Product Overview

### 1.1. Goals
The primary goal of this project is to develop a minimalist, functional URL shortener service. This service will allow users to submit a long URL and receive a unique, short code in return. Subsequently, any request to this short code will redirect the user to the original long URL. The service will prioritize simplicity, clarity, and maintainability, leveraging Python and the FastAPI framework for its API capabilities.

### 1.2. Audience
*   **Developers**: Those who will integrate with the API to shorten URLs or use the service for redirection in their applications.
*   **End-Users**: Anyone who receives or clicks on a shortened URL generated by this service.

### 1.3. Scope
The following features and functionalities are explicitly within the scope of this initial development phase:
*   **API for URL Shortening**: A RESTful API endpoint to accept a long URL (via POST request) and return a newly generated, unique short URL.
*   **API for Redirection**: A RESTful API endpoint that, when accessed with a short code, performs an HTTP 302 (Found) redirect to the original long URL.
*   **Unique Short Code Generation**: Implementation of an algorithm to generate short, alphanumeric codes (e.g., 6 characters long) ensuring uniqueness for each distinct long URL.
*   **In-Memory Persistence**: Storage of the long URL to short code mappings using an in-memory Python dictionary for simplicity. This implies data will not persist across service restarts.
*   **Basic URL Validation**: Input validation for the `long_url` to ensure it's a syntactically correct and functional URL.
*   **Error Handling**: Appropriate error responses (e.g., 404 Not Found for non-existent short codes, 422 Unprocessable Entity for invalid input).
*   **Automated Testing**: Comprehensive unit and integration tests for core logic and API endpoints to ensure correctness and stability.

### 1.4. Out-of-Scope
The following features are explicitly out of scope for this initial phase to maintain focus and simplicity:
*   **Persistent Database**: Integration with external databases (e.g., SQLite, PostgreSQL, MongoDB). The current scope is limited to in-memory persistence.
*   **User Authentication/Authorization**: No user accounts, login, or access control will be implemented.
*   **Custom Short Codes**: Users will not be able to request specific short codes; codes will be auto-generated.
*   **URL Analytics**: Tracking features such as click counts, geographic data, or referral sources for short URLs.
*   **URL Expiration**: Short URLs will not have an expiration date; once created, they will theoretically exist indefinitely (or until service restart with in-memory persistence).
*   **Rate Limiting**: No measures to prevent abuse or excessive API requests.
*   **Frontend User Interface**: No web interface for users to interact with the service beyond direct API calls or visiting short URLs.
*   **Advanced Scalability/Deployment**: No considerations for Docker, Kubernetes, or distributed systems for high availability/scalability in this initial specification.
*   **API Documentation Generation**: While FastAPI supports OpenAPI docs, explicit efforts beyond default generation are out of scope.

## 2. Implementation Tasks

Each task includes a description, its dependencies, and clear success criteria.

### Task 1: Project Initialization and Dependency Setup
*   **Description**: Initialize a Python project, set up a virtual environment, and install core dependencies: FastAPI, Uvicorn (ASGI server), and pytest for testing.
*   **Dependencies**: None.
*   **Success Criteria**:
    *   A `pyproject.toml` (or `requirements.txt`) file lists `fastapi`, `uvicorn`, and `pytest`.
    *   A minimal FastAPI application can be run successfully using `uvicorn main:app --reload`.
    *   A basic test file can execute with `pytest`.

### Task 2: Core Logic - Short Code Generator Module
*   **Description**: Implement a module responsible for generating unique, fixed-length (e.g., 6 characters) alphanumeric short codes. This module should ensure that newly generated codes do not clash with existing ones (though this check will largely be handled by the persistence layer, the generator should aim for high entropy).
*   **Dependencies**: Task 1.
*   **Success Criteria**:
    *   A file `app/short_code_generator.py` exists with a function like `generate_short_code(length: int = 6) -> str`.
    *   Unit tests verify that generated codes are alphanumeric and have the specified length.
    *   Unit tests confirm a high probability of uniqueness over a reasonable number of generations (e.g., 1000 generations produce 1000 unique codes).

### Task 3: Persistence Layer - In-Memory URL Store Module
*   **Description**: Create a module to manage the storage and retrieval of URL mappings using a simple Python dictionary. It should provide methods to save a new mapping, retrieve a long URL given a short code, and check if a long URL already has a short code.
*   **Dependencies**: Task 1.
*   **Success Criteria**:
    *   A file `app/url_store.py` exists containing a class or functions to manage the in-memory store (e.g., `UrlStore.save_mapping(long_url, short_code)`, `UrlStore.get_long_url(short_code)`, `UrlStore.get_short_code(long_url)`).
    *   Unit tests verify that mappings can be added, retrieved, and that looking up a non-existent short code returns `None`.
    *   Tests confirm that attempting to retrieve a `long_url` by an already shortened `long_url` returns the correct `short_code`.

### Task 4: API Endpoint - Shorten URL (`POST /shorten`)
*   **Description**: Implement the API endpoint for shortening URLs. This endpoint will:
    *   Accept a JSON payload with a `long_url` field.
    *   Validate the `long_url` using Pydantic's `HttpUrl` type.
    *   Check if the provided `long_url` already exists in the `UrlStore`. If so, return its existing short URL.
    *   If new, generate a unique short code using the `ShortCodeGenerator`.
    *   Store the mapping in the `UrlStore`.
    *   Construct and return the full short URL (e.g., `http://localhost:8000/abcdef`).
*   **Dependencies**: Task 1, Task 2, Task 3.
*   **Success Criteria**:
    *   `POST /shorten` with a valid, new `long_url` returns HTTP 200 OK with a JSON body containing the generated `short_url`.
    *   `POST /shorten` with a previously shortened `long_url` returns HTTP 200 OK with the *existing* `short_url`.
    *   `POST /shorten` with an invalid `long_url` (e.g., "invalid-url") returns HTTP 422 Unprocessable Entity.

### Task 5: API Endpoint - Redirect Short Code (`GET /{short_code}`)
*   **Description**: Implement the API endpoint for redirecting short URLs. This endpoint will:
    *   Accept a `short_code` as a path parameter.
    *   Attempt to retrieve the corresponding `long_url` from the `UrlStore`.
    *   If found, perform an HTTP 302 Found redirect to the `long_url`.
    *   If the `short_code` is not found, return an HTTP 404 Not Found response.
*   **Dependencies**: Task 1, Task 3.
*   **Success Criteria**:
    *   `GET /{existing_short_code}` returns an HTTP 302 Found redirect to the original `long_url`.
    *   `GET /{non_existent_short_code}` returns an HTTP 404 Not Found response.

### Task 6: Comprehensive Automated Tests
*   **Description**: Write a complete suite of automated tests. This includes unit tests for the `ShortCodeGenerator` and `UrlStore` modules, and integration tests for both API endpoints (`/shorten` and `/{short_code}`) using FastAPI's `TestClient`. Cover happy paths, edge cases, and error conditions.
*   **Dependencies**: Task 2, Task 3, Task 4, Task 5.
*   **Success Criteria**:
    *   All unit tests (for generator, store) pass.
    *   All integration tests (for API endpoints) pass.
    *   Test coverage for `app/` directory (excluding `main.py` if it only contains app instantiation) is above 90%.
